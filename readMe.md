# side_plate 빨간 홈 방향 맞추기 (v2)

카메라로 부품을 찍어서, **빨간 홈(바닥 테두리의 작은 홈) 두 개가 0°(위)와 180°(아래)에 오고 문양(각인 격자/숫자) 쪽이 왼쪽에 오려면** 지금 자세에서 몇 도 돌려야 하는지 계산합니다.
문양을 오른쪽에 두려면 `config.yaml`의 `target.pattern_side`를 `right`로 바꾸세요.

모든 명령은 이 폴더(`~/Projects/direction_recognition_sideplate_v2`)에서 `python3`로 실행합니다.

## 동작 원리

1. **STL 맞추기** (`matcher.py`)
   STL의 꺾인 모서리(긴 홀, 원호 홈, 패드 경계 등)를 영상의 밝기 경계에 맞춰 부품의 회전각과 중심을 찾습니다.
   - 긴 홀 하나가 가운데 허브에 가려도 됩니다. 허브 가림은 STL 높이맵으로 계산합니다.
   - 홀 안으로 비치는 배경(흰 책상, 비닐)이 달라도 영향이 없습니다. 홀 밝기가 아니라 모서리 모양으로 맞추기 때문입니다.
   - 이 카메라 높이(약 66°)에서는 **빨간 홈이 윗판 테두리 밑에 숨어서 거의 보이지 않습니다.**
     그래서 홈을 영상에서 직접 찾지 않고, STL에서 잰 홈 위치를 씁니다. 홈은 긴 홀에서 반시계로 12.6° 떨어진 35°/215°이고, 이것이 "STL 보정"입니다.
2. **문양 쪽 판정** (`decision.py`)
   빨간 홈 두 개를 잇는 선으로 원판을 반으로 나누고 두 반쪽의 값을 비교합니다.
   형상은 180° 대칭이라 두 반쪽은 문양만 다릅니다.
   - 비교 위치는 STL로 정합니다. 평평한 윗면만 쓰고, 홀·홈·허브·단차는 뺍니다. 두 반쪽에서 서로 180° 마주 보는 점끼리만 비교합니다.
   - 기본 특징값 `line_ratio`는 "가는 어두운 선(각인) 세기 ÷ 주변 밝기"입니다.
     흑백 카메라라서 RGB 합(`rgb_sum`)은 밝기의 3배와 같습니다. 그런데 화면 위·아래 조명 치우침(약 10%)이 문양 차이보다 커서, 기준 사진 4장 중 3장에서 판정이 뒤집혔습니다. `rgb_sum`을 쓰려면 기준선(`--fit-baseline`)을 꼭 만드세요.
   - STL에 들어 있는 문양 모서리(격자)와도 맞춰 보고, 반쪽 비교 결과와 다르면 `low_confidence`로 알립니다.
3. **회전각**: 문양 쪽 가운데가 목표 방향(왼쪽 = 270°)에 오도록 돌릴 각도를 계산합니다. 그러면 빨간 홈은 자동으로 0°/180°에 옵니다.

STL 정보는 `python3 stl_model.py SIDE-PLATE-BP.stl images/model_topview.png`로 확인합니다.
홈은 35°/215°, 긴 홀은 22.4°/202.5°, 문양 중심은 288°입니다(STL 좌표, 반시계 +).
바닥에는 168.5°/348.5°에 폭 3°짜리 홈이 하나 더 있습니다. 이 홈을 기준으로 하려면 `stl.notch_angle_deg: 168.5`로 지정하세요.

## 0. 준비

- **MVS 클라이언트를 닫으세요.** 열려 있으면 "카메라를 다른 프로그램이 쓰고 있습니다" 오류가 납니다.
- 조명과 부품 위치는 측정할 때와 똑같이 맞춰 둡니다.

## 1. 보정 (카메라를 설치하거나 옮겼을 때 1회)

지금 `calib.yaml`은 현재 카메라 설치(고도각 약 55°, 부품 중심 약 (2037, 2026) px)에서 찍은 `images/live/now_1.png`로 만든 것입니다.
원판 테두리를 자동으로 찾아 타원을 맞춘 뒤 STL로 다듬었습니다.
카메라와 부품 놓는 자리가 그대로면 이 단계는 건너뛰어도 됩니다.
예전 설치(`images/base` 사진, 고도각 66°)의 보정은 `calib_base_setup.yaml`에 있습니다. 그 사진을 다시 돌릴 때는 `--calib calib_base_setup.yaml`을 붙이세요.

```bash
python3 calibrate.py click --camera            # 촬영 → 원판 윗면 바깥 테두리를 8~12점 클릭 → Enter
python3 validate.py capture --out images/base --step 90   # 0/90/180/270° 로 돌려 찍기
python3 calibrate.py refine images/base/rot_*.png         # STL 로 중심/크기 다듬기
```

클릭 창 단축키는 z(마지막 점 취소), r(전체 초기화), q(취소)입니다.

## 2. 측정 (평소 사용)

```bash
python3 side_plate_notch.py --camera --debug debug.jpg
```

출력 예:

```
상태: 정상
  돌릴 각도: -54.20°  (반시계방향 54.20°, 스테이지 명령 -54.20°)
  현재 빨간 홈: 54.2°, 234.2°   긴 홀: 66.8°, 246.7°   (12시=0°, 시계방향 +)
  현재 문양 쪽 가운데: 324.2°  → 목표 270° (왼쪽)
  회전 후 빨간 홈: 0.0°, 180.0°
  문양 판정(line_ratio, 반쪽 전체): 문양 쪽 0.0755 / 반대쪽 0.0456  (차 24.6%)   STL 문양 확인: 일치
  STL 맞추기: 점수 0.526, 봉우리비 1.71, 중심 (2726, 2375) px
```

- `돌릴 각도`(`rotate_cw_deg`): 위에서 볼 때 시계방향 +, 음수면 반시계입니다. 스테이지 방향이 반대면 `output.rotate_sign: -1`로 바꾸세요.
- 상태 값:
  - `정상`(ok)
  - `문양 판정 불확실`(low_confidence): 두 반쪽 차이가 작거나 STL 문양 확인과 다름
  - `각도 불확실`(angle_uncertain): 봉우리비가 낮음
  - `부품을 못 찾음`(not_found)
- 다른 프로그램과 연동할 때는 `--json`(JSON만 출력)을 쓰고, 찍은 사진을 남기려면 `--save images/now.png`를 붙입니다.
- 사진 파일로 측정: `python3 side_plate_notch.py --image a.png b.png --debug 폴더/`
- 디버그 그림에서는 빨간 선이 빨간 홈 선, 호박색이 문양 쪽 반쪽, 청록이 반대쪽, 초록 점이 STL 모서리입니다.
  초록 점이 긴 홀 테두리에 올라가 있는지 확인하세요.

## 3. 정확도 검증 (권장)

```bash
python3 validate.py capture --out images/val --step 30 --repeat 2
python3 validate.py analyze images/val --debug-dir images/val/debug
```

자세별 오차, 반복성, 문양 180° 오판 수를 출력하고 `results.csv`로 저장합니다.
**회전 스테이지나 각도기로 정확히 돌려 찍어야 오차를 믿을 수 있습니다.**
`images/base`는 손으로 대충 돌린 사진이라 "오차"가 최대 9°로 나오지만, 실제 회전량 자체가 부정확합니다(v1도 같은 사진에서 비슷한 불일치를 냈습니다).

## 파일

| 파일 | 내용 |
|---|---|
| `side_plate_notch.py` | 측정 (메인) |
| `calibrate.py` | 보정 (테두리 클릭 → STL로 다듬기) |
| `validate.py` | 정확도 검증 (촬영 / 분석) |
| `config.yaml` | 설정 (목표 자세, 카메라, 판정 방법) |
| `calib.yaml` | 보정 결과 (`.bak` = 직전 파일) |
| `calib_base_setup.yaml` | 예전 카메라 설치(`images/base`)의 보정 |
| `images/live/` | 실제 카메라 측정 사진과 디버그 그림 |
| `stl_model.py` | STL 분석 (회전축, 높이맵, 모서리 점, 홀/홈/문양 위치) |
| `matcher.py` | 카메라 모델 + STL 모서리 맞추기 |
| `decision.py` | 빨간 홈 선으로 반쪽 비교 |
| `hik.py` | Hikvision 카메라 촬영 (MVS SDK) |
| `common.py` | 공통 (설정, 각도, 한글 글자) |
| `cache/` | STL 분석·가림 표 캐시 (지워도 다시 만들어짐) |
| `tools/` | 개발용 시험 스크립트 |
